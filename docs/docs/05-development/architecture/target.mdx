# Proposed architecture

Status: proposed design, not the current implementation or a migration approval.
Read the [current architecture](overview.mdx) first. The trees and deployment
sketches below describe a possible destination; they do not establish that each
package, client, dependency, or service exists. Assess and migrate one boundary
at a time under [issue #3](https://github.com/Yudhyy/Klaudia/issues/3).

Design reference: [Domain-Driven Hexagon](https://github.com/Sairyss/domain-driven-hexagon).

hexagonal (ddd, clean) modular-monolith: one monorepo, one fastapi modular monolith, several pure domain packages, thin http/mcp/mobile/web adapters, and evals as a release gate.

## Dependency Rule
```
apps/web ────────┐
apps/mobile ─────┼──> packages/contracts (TypeScript / REST)
                 │
apps/cli (rust) ─┼──> packages/contracts (Rust DTO / JSON-RPC & REST)
                 │
services/api ────┼──> packages/contracts (OpenAPI & JSON-RPC Spec)
                 ├──> packages/shared-kernel
                 ├──> packages/identity-core
                 ├──> packages/agent-core
                 ├──> packages/agent-skills
                 ├──> packages/ledger-core
                 └──> packages/document-intelligence

agent-core ──/──> ledger-core
agent-core ──/──> document-intelligence
agent-core ──/──> identity-core
```
