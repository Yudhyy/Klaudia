Procedure:
1. Use this procedure only for typed inputs and native decimal formulas when inspect_typed_workbook and prepare_typed_edit are enabled. This format is not Excel syntax. Supported operations are add, subtract, multiply, divide, sum, round, roundup and rounddown. Dependencies may cross sheets within one owned workbook; cross-workbook links are rejected.
2. Resolve the requested destination before editing. When the user names a workbook, use search_resources and compare returned workbook_name with that name before selecting its spreadsheet_id. Never assume the active workbook matches a named destination: ownership is permission, not intent. If discovery cannot resolve the name, ask for clarification instead of writing to the active workbook. For a request that explicitly targets the active workbook, its server-provided ID is available as a hint. Use placement inspection if needed to confirm raw cells. inspect_typed_workbook returns managed cell IDs, typed values, expressions, statuses, sheet identities and an opaque snapshot fingerprint. It does not return unrelated grid contents or verify a workbook's name. Keep the fingerprint unchanged in the proposal; any workbook grid, revision or managed declaration change invalidates it.
3. prepare_typed_edit takes workbook_id, snapshot and edits. Each edit has action, sheet_id, row and column; row/column are one-based. set_input also requires input with kind (decimal/text/boolean/date), exact value and optional unit/display_format. Decimal values must be plain decimal strings, booleans real booleans, dates YYYY-MM-DD. Do not infer locale or reinterpret existing codes as amounts. Creating a declaration is an explicit write of the supplied value, not automatic migration. Existing unrelated cells remain unchanged.
4. set_formula takes a formula object and optional unit/display_format. formula has operation, operands and rounding. Each operand is exactly {"literal":"0.1"} or {"cell_id":"observed stable ID"}. Declare inputs and execute them first, then inspect their IDs before preparing formulas. Complex calculations compose through computed cell dependencies. A direct cross-sheet reference uses sum with one cell operand. Never invent cell IDs or send an Excel expression such as =Sheet2!A1.
5. Every persisted formula requires rounding with places 2 or 4 and mode ROUND_HALF_EVEN or ROUND_HALF_UP, chosen from the user's currency/tax convention. Ask when the convention is missing. round has one operand and uses one of those two modes. roundup has one operand and requires ROUND_UP (away from zero); rounddown requires ROUND_DOWN (toward zero). Binary arithmetic requires two operands; sum accepts one to 64. Rounding applies once to each persisted computed result; downstream formulas consume that rounded value. Do not infer unit conversions or dimensional accounting rules.
6. Execute the original prepared reference through execute_operation. Preparation changes no cells. Respect any approval wait and resume the original reference after a decision. Never prepare a replacement to recover an unknown write outcome. The backend locks the workbook and all its sheets, checks the snapshot again, and commits input changes, formula state, exact cached values and a receipt together.
7. set_input cannot replace a computed cell. Ordinary grid writes cannot change managed inputs or computed values, alter managed sheet layout or delete a managed sheet. Unrelated same-layout grid cells remain editable. Sheet renames retain stable cell references. Formula removal and structural movement of managed cells remain unsupported. Typed edits cannot change registered table headers.
8. Inspect calculation_status separately from status=committed. not_required means the workbook had no formulas; current means the bounded graph recalculated without failed results; failed means at least one formula failed. Failed results have null cache values and explicit errors, and dependent failures propagate. Ordinary grid reads and deterministic calculations reject sheets with pending/failed formulas so they cannot silently report zero. Use typed inspection to inspect and repair failures.
9. Receipts state invalidated dependency count and actual recalculated count. The bounded implementation recalculates all managed formulas after a checked edit, including formulas outside the affected subset. Cycles, unknown/non-decimal dependencies and cross-workbook references reject the proposal. Decimal operands have a 64-digit budget; intermediate arithmetic is rational and the final scale is explicit. Invalid or overflowing calculations report failure, never an approximate current value.
10. Typed edits leave registered catalogue observations stale. Follow the existing checked table-authoring refresh before calculate or financial_query. Receipts retain changed sheet revisions; inspect again before the next edit. Display formats are stored metadata, not a rendering engine or arithmetic input. No legacy strings or formats are guessed or migrated automatically.
11. Limits: eight sheets, 1 MiB source grids, 64 registered tables and 256 managed cells per workbook; 32 edits per proposal, 64 operands per formula, 65536-byte request and evidence budgets. This is bounded synchronous execution, not background recalculation. These receipts do not establish accounting correctness or final-prose metric-label correctness.
12. Keep the final answer to the requested outcome and relevant limits, normally two to four sentences. For an input edit, name the input and any dependent formula result that changed. For formula creation or replacement, the definition and cached value belong to the same target cell; do not describe them as separate cells. Report a committed failed formula as a stored definition with no valid calculated value, not a completed financial result. If explaining division, the first operand is the numerator and the second is the divisor; prefer the actual expression over unnecessary terminology. Formula replacement is supported; formula removal is not supported. These calculation receipts do not establish accounting correctness; report their accounting validation status only when relevant to the request. Do not offer unrelated operations or repeat internal IDs and revision tables unless requested.
