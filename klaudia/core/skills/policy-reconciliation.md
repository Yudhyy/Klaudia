Procedure: policy-backed reconciliation

1. Use this procedure for accounting reconciliation. Read `/accounting-policy.md` with `read_memory_document`. An active document must include structured `policy` metadata; prose or preferences alone are insufficient. Missing, deleted or unavailable policy blocks this work. Ask the user to save or correct it through authenticated context editing. Do not invent or edit policy.
2. Confirm the intended entity, jurisdiction and as-of date. The date selects the inclusive policy validity period; it does not filter transaction rows. Jurisdiction is a caller declaration matched to the saved policy, not a legal or tax determination.
3. Discover the intended owned tables and inspect their columns. Both registered entity labels must exactly match the policy entity. Do not substitute the active workbook for a named source. Resolve unclear source selection with the user.
4. Call `reconcile_with_policy` with both table IDs, paired exact key columns, amount columns, explicit unit columns, the entity, jurisdiction, as-of date and observed policy revision. The backend supplies tolerance, numeric-text handling, null-amount handling and null-key handling from saved metadata. Each source unit column must match the saved unit. No unit conversion occurs.
5. The backend checks current ownership and binds entity inspection to the same source revisions used by calculation. It checks policy revision again after calculation. A stale source or policy requires a new read; do not replace errors with model arithmetic or a generic financial query.
6. All registered rows participate in a full outer, unique-key comparison before pagination. `as_of` is not a date filter. Missing sides remain left-only or right-only. Blank amounts follow saved policy; excluded values are counted rather than treated as zero. Duplicate keys require a business decision or a separately prepared source. Differences are exact; no rounding is applied.
7. Bind each reported difference to that record's key and copy its exact `difference` value. A row difference and a combined difference are distinct metrics: never label a combined amount as one row's result. Preserve the user's requested labels verbatim. Before answering, check each labelled amount against the matching record, not merely against numbers appearing elsewhere in the evidence.
8. Explain left-minus-right differences, unit, tolerance, full-population counts, page limits, policy revision and source revisions. `policy_parameters_checked` means these bounded checks passed, not that legal compliance or full accounting correctness was certified. Never call a truncated record page a complete reconciliation. This tool does not write ledger records.
